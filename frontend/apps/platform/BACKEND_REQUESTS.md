# Backend requests from the platform console

The console uses only the routes in `docs/api.md`. These are gaps against `MASTER_UI.md` section 8. Each is **requested**, not built. The console labels the missing feature honestly until the route exists. Shapes are proposals for Ibtasaam to accept or change.

Same-origin deployment (console served by the backend at `/`) means no CORS request is needed for the console.

| #   | Gap                                                    | Status    | Requested route and shape                                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Job list (MASTER_UI 8.4 `/`)                           | requested | `GET /api/drafts?limit=50` → `[{"id","version","status","filename","row_count","profile_id","created_at","updated_at"}]`, newest first. Until then: "Jobs created in this browser" from localStorage.                                                                                      |
| 2   | Draft metadata for job header                          | requested | Add `filename`, `created_at`, `updated_at`, `profile_id`, `review_id`, `receipt_id` to `GET /api/drafts/{id}`. Also: this route returns `id` while others return `draft_id`; please confirm which is canonical.                                                                            |
| 3   | Draft status values                                    | requested | Document the full `status` enum (seen: `uploaded`, `inspected`) so the stepper can map it to Intake/Profile/Run/Review/Release.                                                                                                                                                            |
| 4   | Authentication (MASTER_UI 8.2)                         | requested | Verify `Authorization: Bearer <Firebase ID token>` on `/api/*`; 401 when missing/invalid, 403 when not allowed. Console sends the header only when `config.json` has `"auth": "firebase"`.                                                                                                 |
| 5   | Live run events (MASTER_UI 8.5 Run)                    | requested | `POST /api/drafts/{id}/review` returning `202 {"run_id"}`, plus `GET /api/drafts/{id}/events?after=<seq>` → `{"events":[{"seq","at","kind","tool","summary","status","duration_ms"}],"next":<seq>}`. Until then: honest waiting state, then `activity` after the synchronous call returns. |
| 6   | Activity and outcome item shapes                       | requested | Document `review.activity[]`, `plan.planner_activity[]`, and `outcomes[]` fields (e.g. `{"at","tool","model","summary","status","duration_ms","error"}`). Rendered as raw JSON fields until documented.                                                                                    |
| 7   | Audit trail (MASTER_UI 8.4 `/activity`)                | requested | `GET /api/audit?draft_id=&limit=` → `[{"at","actor","action","draft_id","version","finding_id","detail"}]`, and `GET /api/drafts/{id}/history` → versions, corrections and decisions with reasons.                                                                                         |
| 8   | Check catalog details (`/checks`, Profile step)        | requested | `GET /api/checks` → `[{"id","name","purpose","columns","parameters","prerequisites","procedure"}]`. `available_checks` is only IDs today.                                                                                                                                                  |
| 9   | Profile detail and versions (`/profiles/:id`)          | requested | `GET /api/profiles/{id}` → full profile incl. `required_fields`, `unique_fields`, `answers`, `reference_id`, `created_at`, `versions[]`.                                                                                                                                                   |
| 10  | Question options                                       | requested | MASTER_UI wants several suggested answers per question: `questions[].options: string[]` and `questions[].required: boolean`. Today one `suggested` string.                                                                                                                                 |
| 11  | Profile reuse compatibility                            | requested | `GET /api/drafts/{id}/plan?reuse_profile_id=` (or a field on plan) → `{"compatible": bool, "reasons": [...]}` so the console can show why a saved profile matches.                                                                                                                         |
| 12  | Inspection warnings shape                              | requested | Document `inspection.warnings[]` (e.g. `{"code","message","rows":[...],"column"}`) and per-column mixed-format examples.                                                                                                                                                                   |
| 13  | Feedback effect on ranking (MASTER_UI 8.5 Review)      | requested | `findings[].ranking_note` (e.g. "Ranked lower: you dismissed 2 similar findings") when feedback changed rank.                                                                                                                                                                              |
| 14  | Request ID on errors (MASTER_UI 5.6)                   | requested | `X-Request-ID` response header on every `/api/*` response, echoed in logs.                                                                                                                                                                                                                 |
| 15  | Public widget routes (MASTER_UI section 9, portal 7.4) | requested | `POST /api/public/submissions` (header `X-Publishable-Key`, multipart `file`, `return_url`) → `{"job_id","status","platform_url"}`; `GET /api/public/submissions/{id}` → `{"status","accepted_count","held_count"}`; `GET /api/public/accepted` → accepted rows for the portal table.      |
| 16  | Procedure pages                                        | requested | Confirm `findings[].procedure` (`/procedures/...`) is served by the backend as a page. The console opens it as a normal link.                                                                                                                                                              |
| 17  | Decisions list                                         | requested | Include recorded decisions on the review (`findings[].decision`, `reason`, `decided_at`) so the console can show which findings were already verified or acknowledged.                                                                                                                     |
